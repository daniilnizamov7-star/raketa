# Восстановление на другом хостинге

## Что потребуется

Репозиторий содержит файлы сайта, резервную афишу в afisha-config.js и структуру новой базы в database/schema.sql. История заявок для запуска не требуется.

Рабочий config.php нужно заранее сохранить вне хостинга в защищённом хранилище владельца. В нём находятся настройки базы, почты, Telegram и хеш пароля афиши. GitHub содержит только config.example.php с заглушками. Для новой базы задаются новые реквизиты. При использовании прежней почты и бота их действующие реквизиты переносятся владельцем из защищённой копии.

## Подготовка хостинга

Нужны PHP с PDO MySQL, mbstring, cURL, JSON и OpenSSL, база MySQL или MariaDB, исходящие соединения к SMTP по SSL на порту 465 и к api.telegram.org по HTTPS. Текущий сайт проверен на Beget с PHP 8.5. На другом провайдере требуется проверка перед переключением.

1. Создайте сайт и отдельную пустую базу с пользователем.
2. В phpMyAdmin выберите новую базу и импортируйте database/schema.sql. Файл создаёт три таблицы без заявок. Применяйте его один раз к пустой базе.
3. Загрузите файлы сайта, включая assets/, admin/ и .htaccess. Каталоги .git/, docs/ и database/, а также AGENTS.md, README.md, VERSION.md и config.example.php оставьте вне публичной папки.
4. Скопируйте config.example.php в config.php на сервере, заполните все заглушки и проверьте синтаксис через php -l config.php. Пароли со специальными символами должны быть корректно экранированы для PHP.
5. Для Telegram укажите действующий токен и chat ID. Константу TG_NO_DIRECT оставьте неопределённой, чтобы обработчик отправлял уведомления напрямую.
6. Для редактирования афиши перенесите действующий AFISHA_PASS_HASH либо создайте новый хеш через password_hash с PASSWORD_DEFAULT локально. Убедитесь, что пароль редактирования известен владельцу.
7. На Apache проверьте применение .htaccess. Для Nginx или Caddy настройте эквивалентный запрет доступа к config.php, config.example.php, birthday-engine.php, birthday-catalog.json, скрытым файлам и архивам, SQL и резервным копиям. Отключите список файлов каталогов.

## Афиша

Если изменения вносились через /admin/, актуальная афиша хранится в таблице raketa_afisha. Чтобы сохранить её без заявок, в phpMyAdmin экспортируйте только эту таблицу. Структура уже входит в schema.sql, поэтому для последующего импорта после схемы выберите экспорт только данных. Храните файл вне публичной папки. При аварии можно восстановить афишу вручную через админку по опубликованному расписанию.

Если такой копии нет, сайт использует резервную афишу из afisha-config.js. Её актуальность и срок validUntil нужно проверить. Новые картинки, добавленные при обновлении сайта, тоже должны попасть в репозиторий.

## Проверка и переключение

1. До смены DNS откройте новую копию через технический домен или локальное соответствие домена и нового IP. Проверьте главную, изображения, меню и калькулятор. Для админки используйте основной домен через локальное соответствие, поскольку разрешённые источники API перечислены в afisha-api.php.
2. Проверьте HTTPS основного домена и www и редирект HTTP на HTTPS. Если сертификат требует переключения DNS, выполните выпуск сразу после него.
3. Отправьте одну явно обозначенную тестовую заявку на свой номер. Подтвердите фактическое получение писем и Telegram. Ответ формы сам по себе не подтверждает доставку обоих уведомлений.
4. Проверьте чтение афиши и вход в её редактор.
5. Сохраните DNS-зону и прежние адреса для отката. Поменяйте A-записи основного домена и www на новый IP. Проверьте AAAA-записи, если они есть. При смене DNS-провайдера перенесите MX, TXT и остальные поддомены, затем измените NS у регистратора.
6. Повторите пользовательский сценарий по основному домену. Проверьте, что config.php возвращает 403 или 404 и его содержимое недоступно.
7. До завершения обновления DNS оставьте прежнюю копию или прокси для старых кешей. Если старая копия продолжает принимать заявки, проверьте их доставку перед отключением.
8. При сбое верните прежние записи DNS и настройки. Обновление кешей может занять время.

## Что подготовить заранее

- Доступ к REG.RU и DNS независимо от хостинга.
- Актуальный репозиторий и защищённую внешнюю копию config.php.
- Экспорт данных только raketa_afisha после её изменений либо актуальную резервную афишу в репозитории.
- Доступность выбранной почтовой службы при аварии хостинга. Если почта также обслуживается недоступным провайдером, потребуется другой SMTP-сервис и его SPF/DKIM/DMARC.
- Проверенный доступ менеджера к Telegram и адресу получения писем.

Этот комплект подготовлен по работающему коду и структуре снимка Selectel. Полное восстановление на третьем хостинге ещё не проводилось.
